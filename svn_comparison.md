# Git и SVN: краткое сравнение

## 1. Почему ветки в Git считаются лёгкими?

Ветка Git — это небольшой указатель на коммит. Создание ветки не копирует весь проект, а переключение между ветками работает локально. В SVN ветка представлена путём в центральном репозитории; современная SVN делает server-side copy эффективно, но Git всё равно удобнее и быстрее для частых локальных ветвлений.

## 2. Можно ли сделать commit в SVN без сети?

Нет, обычный SVN commit должен обратиться к центральному серверу. Изменения можно редактировать офлайн, но зафиксировать их на сервере получится после подключения. В Git commit сохраняется локально, потому что у разработчика есть полноценная копия истории.

## 3. Когда SVN может быть удобнее?

SVN подходит командам, которым нужна централизованная история и права доступа на уровне отдельных каталогов или файлов, либо блокировки файлов, которые трудно сливать (например, некоторые бинарные ресурсы). Это особенно полезно, когда так устроена существующая инфраструктура команды.
